# Street NPC reactions to gunfire and near misses

For response timing, follow the hit from `confirmReaction` through `TrafficAmbient.wakeReaction` to the HLC assignment. A confirmed player hit wakes its victim in the same server callback. The syncer steers away from the threat while the server requests a reachable path node. When a waypoint arrives, the same flight continues along the graph. Damage received while airborne still goes through landing recovery. Listening peds keep their current movement input during their personality delay, then share a bounded wake queue behind direct interactions. Run `python -B tools/check_vcs_traffic.py` for the 80-ped timing and client input regression.

Addresses refer to US PS2 `SLUS_215.90`, SHA-256 `3b43be57d60a29df35e41504d67bbf728d5ce2fc5aab6bbf928cbbc5963fe547`. The table records call chains checked through Ghidra MCP. Data offsets refer to the decompressed `PS2/GAME.DTZ`.

## MTA adapter

The server receives player shots through `onPlayerWeaponFire`. The minigun occupies slot 7 and falls outside MTA's server bullet event, so the client supplies a rate-limited local firing event. The server checks the holder and current weapon. Managed NPCs use `onClientPedWeaponFire` reports from their syncer; the server checks entity, synchronization authority, space and equipped weapon. Hearing accepts bullet weapons and ped shooters. The wanted system handles shots and damage independently. [MTA firing event](https://wiki.multitheftauto.com/wiki/OnPlayerWeaponFire), [weapon synchronization table](https://wiki.multitheftauto.com/wiki/Weapons).

Each shooter's hearing scan runs at most once per second. It filters listeners by original distance, type mask and personality. The PS2 executable walks a global event pool each frame; MTA dispatches events in the active area. Police turn toward a neutral player's shot and can intervene when the player is already wanted. That connection uses MTA's existing wanted state. Special hiding spots, story flags and dynamic gang hostility have only partial equivalents in this module.

Near-miss evasion uses the shot endpoints supplied by MTA, samples one shot in four on average and preserves the low-five-bit probability check. The port additionally requires point-to-segment distance below 2 to exclude peds far from a long diagonal shot inside the original bounding box. The victim's syncer checks for a safe landing to either side. An accepted dive runs the bundled PS2 EV_dive and get-up clips through the same revisioned playback as vehicle evasion. Hearing uses the shooter as the event origin; streets and bullet endpoints do not generate secondary shot events.

In this port, every accepted flee reaction uses sprint for local steering and graph waypoints. The original speed choices are recorded above.

The stairway at `(-1056.736816, 1267.409302, 10.622761)` is a stationary-player regression location. Nearby pedestrian nodes include 7495�7498. For a live check, let ambient traffic populate the area, fire a shot, and follow individual pedestrians through the reaction and route handoff. Inspect the collision surface along the stairs when a graph node lies below a tread.

Actual frightened flight or evasion triggers `fear`. A driver being carjacked uses `carjack`. Each attributed injury submits one voice request even when the personality declines to fight back. Gunshot wounds use `pain`, and physical hits use `impact`. Ordinary punches reuse the verified impact pool; original per-punch voice selection still requires verification. See [voice call evidence](vcs-voice-calls.md) for queueing, distance and cooldown.

Run `py -B tools/ped_ai_check.py` to check the 60-unit boundary, dimension isolation, delay, gait, faction filtering, police intervention, near-miss boundaries, player and syncer attribution, and duplicate voice suppression. Run `py -B tools/ped_ai_profiles.py <disc-directory> --check` to verify the generated data.
